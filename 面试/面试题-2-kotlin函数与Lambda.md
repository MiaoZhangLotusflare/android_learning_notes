# 面试题 - 2 - Kotlin 函数与 Lambda

## 1. 扩展函数到底是什么原理？能重写吗？

<mark>对象声明、嵌套对象、伴生对象</mark>

<mark>reified</mark>

扩展函数在 kotlin 中是为现有类和接口添加额外功能的好方法。顶层扩展函数不属于任何类，能在任何类里使用它。

**扩展功能的优势**：

* 清洁守则：扩展函数允许以非侵入式的方式添加使用函数，使代码更具模块化和可维护性。

* 提升可读性：可以用针对应用或领域的特定行为来增强现有类，而不会让它们的原始代码变得杂乱。

* 提升可重复使用性：扩展函数允许创建可重复使用的函数，这些函数可以应用于同类型的各种对象。

* 

**扩展函数原理**：编译为静态函数，调用对象是静态函数的第一个参数。在编译期决定调用哪个扩展属性，不看运行时的实际类型。

**接收者类型就只能类或者接口吗？** 不完全是，接收者写的是一个类型，类和接口只是最常见的两种，还有可空类型、泛型类型、类型参数本身、函数类型、枚举、对象声明、抽象类等都可以作为接收者类型。

**扩展函数能访问类私有的或者受保护的成员吗？** 顶层扩展函数可以访问被扩展类的公开的属性与函数（同模块里还有 internal），不能访问私有与protected 属性与函数；成员扩展函数可以访问外层类的公开、私有、protected 、internal 的属性与函数，但是只能访问被扩展类的公开的属性与函数（同模块里还有 internal）。因为扩展函数实际上是静态函数，调用对象是静态函数的第一个参数。

**扩展函数可以重写吗？** 普通的扩展函数不能重写，因为它不是类的成员，调用哪个版本在编译期就按接收者的声明类型定了，和运行时的实际类型无关。也就是说，调用哪个扩展函数，取决于接收者的静态类型，而不是接收者的运行时类型。

成员扩展函数可以重写，被重写的是外层类的那个成员，多态看的是外层对象，接收者仍然按声明类型静态选择。

**类的扩展函数和成员函数签名相同，谁会被优先使用？** 成员函数会被优先使用。

**扩展函数的接收者的本质是什么？** 扩展函数的接收者是表明那个接收者接收了这个扩展函数，就只能由那个类型的对象才调用这个函数。接收者只拥有扩展函数的调用权，而不是扩展函数的所有权。接收者接收了扩展函数的调用权而已，是扩展函数的设计者把这个扩展函数的调用权给了接收者。

**成员扩展函数**：在另一个类中为另外一个类声明扩展函数，即是外部类的成员函数，又是前缀类的扩展函数。由于是成员函数，所以只能在它所属的类里面被调用，到了外面就不能用了。

**当分发接收者和扩展接收者的成员之间出现命名冲突时，会优先使用哪个成员？** 在扩展函数中调用的方法，分发接收者和扩展接收者都有相同的方法时，优先使用扩展接收者的方法。

**成员扩展函数可以重写吗？** 可以，成员扩展函数可以声明为 open，并可以在子类中重写。

**成员扩展函数与顶层扩展函数的区别是什么？**

| 比较项          | 顶层扩展函数    | 成员扩展函数            |
| ------------ | --------- | ----------------- |
| 编译后的 Java 函数 | 静态函数      | 成员函数              |
| 作用域          | 可以在任何地方调用 | 只可以在声明它的类中调用      |
| 函数引用         | 可以引用      | 不可以引用             |
| 可以重写？        | 不可以       | 可以                |
| 接收者          | 存在一个扩展接收者 | 存在一个分发接收者和一个扩展接收者 |

扩展属性：给现有类增加一个访问的属性，同时不修改这个类的源码，需要添加 getter/setter 方法，没有字段，也不能写初始值，结果不会保存在对象里。



扩展属性原理：顶层扩展属性会变成文件生成类里的静态方法，接收者作为第一个参数。解析时机也和扩展函数一样，编译器看变量的声明类型，在编译期决定调用哪个扩展属性，不看运行时的实际类型。

```kotlin
fun String.addExclamation() = this + "!"

// 编译后等价于
public static final String addExclamation(String $receiver) {
    return $receiver + "!";
}
```

kotlin 如何决定调用哪个扩展函数：kotlin 在编译期就选定扩展函数，看的是变量的声明类型，不是对象运行时的实际类型。
